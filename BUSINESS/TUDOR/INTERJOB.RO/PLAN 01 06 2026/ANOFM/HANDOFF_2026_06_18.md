## Fixes Applied (This Session)

### 1. ANOFM_ANGAJATORI — exit 2 (FIXED)

**Original (WRONG) diagnosis:** "missing BREVO_WAREHOUSEWORKERS_API_KEY in env"
**Actual cause:** Orchestrator `build_cmd` appends `--delay 480` (from `delay_s:480`), but ANOFM's argparse only accepted `--limit/--dry-run` → argparse exits code 2. The API key has a hardcoded fallback in the script, so the env var was never the problem.

**Fix:** Added `--delay` and `--daily-cap` arguments to `campaign_anofm_angajatori.py`. Also refactored it to delegate sending to shared `sender.py`.

**Backup:** `campaign_anofm_angajatori.py.bak_20260618_065226`

### 2. Shared sender.py module (NEW)

**Created:** `/opt/ACTIVE/EMAIL/CAMPAIGNS/SCRIPTS/SHARED/sender.py`

All 8 active Brevo+Gmail campaigns now delegate their send logic to this shared module instead of having 12 separate inline send functions. Functions:
- `send_brevo(api_key, sender_email, sender_name, to_email, subject, body, reply_to)` — Brevo HTTP API
- `send_gmail(sender, password, to_email, subject, body, reply_to)` — Gmail SMTP STARTTLS:587
- `add_common_args(parser)` — adds `--dry-run`, `--limit`, `--daily-cap`, `--delay`
- `effective_limit(args, sent_data, today)` — computes how many more to send today

### 3. DEFICIT_CONSTRUCTII/HORECA/PRODUCTIE/TRANSPORT (FIXED)

**Cause:** `import sys` placed before shebang line in some files (was pre-fixed), but more importantly these scripts had no `--delay`/`--daily-cap` args (same ANOFM pattern).

**Fix:** Refactored all 4 to delegate to `sender.py`, accept `--delay`/`--daily-cap`. Dead imports removed (BREVO_URL x6, urllib, smtplib, MIMEText, formataddr, requests, base64, json).

**Backups:** `campaign_{constructii,horeca,productie,transport}.py.bak_20260618_065226`

### 4. SME_DEFICIT, FACTORY_RO, PRIMARII (REFACTORED)

Same refactor: delegate to `sender.py`, accept new args, remove dead imports.

**Backups:** `campaign_{sme_deficit,factory,primarii}.py.bak_20260618_065226`

### 5. NECALIFICATI (DISABLED — blocked on dead key)

**Cause:** Brevo `HTTP 401 {"message":"Key not found"}` — the careworkers API key is dead. Also `romania_send_log` table missing `company_name` column.

**Action:** Set `enabled: false` in campaigns.json. Will re-enable when a valid BREVO_CAREWORKERS_API_KEY is provided.

### 6. EXPORT_AT / "Pepeni" watermelon campaign (FIXED + ENABLED)

**Bug:** Script opened ONE `smtplib.SMTP_SSL` connection outside the loop, then slept 600s between sends. Gmail closes idle connections, so every send after the first sleep failed with `please run connect() first`.

**Fix 1 (connection):** Open+login a fresh SMTP_SSL connection per recipient inside the loop.
**Fix 2 (attachments):** Read JPEG attachments once before the loop as `(name, bytes)` tuples instead of re-reading from disk per recipient.
**Fix 3 (management):** Moved from fragile manual `nohup` to the 24/7 orchestrator. `enabled: true`, `daily_limit: 25`, `daily_cap: 25`.

**Backup:** `campaign_export_at.py.bak_20260618`

**Verified live:** `[1/23] SENT -> altschachl-kraeuter@aon.at` with attachments, no connection errors.

### 7. Duplicate orchestrator service (FIXED)

**Problem:** `/etc/systemd/system/interjob-campaigns.service` was a duplicate of `campaign-orchestrator.service`. Used venv python + `Restart=always`. Exited 0 each time (real orchestrator held the flock lock), then systemd restarted it every 30s — **5453+ restarts**, pure journal spam + wasted cycles.

**Fix:** `sudo systemctl stop interjob-campaigns.service && sudo systemctl disable interjob-campaigns.service`

**Real orchestrator:** `campaign-orchestrator.service` (PID varies, uses `/usr/bin/python3`)
